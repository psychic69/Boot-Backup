VERSION HISTORY
───────────────────────────────────────────────────────────────

1.3.0 - 2026-11-11
  - Removed all remote backup code: dr_usb_backup.sh -remote, lib/remote.sh, remote.ini.example, the remote-mirror
    check in dr_usb_scrub.sh and the REMOTE_INI setting. notify_failure is kept and now also fires on a failed local
    backup; NOTIFY_ON_FAILURE moved to dr_usb.ini. New license-slot warning in the docs

1.2.3 - 2026-11-11
  - lib/remote.sh: the -remote restriction check runs `id` instead of `true` (rrsync 3.4.1 accepts a bare `true`, which made
    a correctly restricted key look unrestricted) (D-1.2.3-01)

1.2.2 - 2026-11-11
  - move_dr_to_unraid.sh: waits for a USB stick that drops off mid-restore and finds it again by filesystem UUID
    (D-1.2.2-01); a USB stick already labelled UNRAID that still has its BACKUP-* marker is resumed (D-1.2.2-02)

1.2.1 - 2026-11-09
  - move_dr_to_unraid.sh: the UNRAID label is read with blkid -p (fallbacks lsblk, fatlabel last line), flushed first,
    retried for ~30s, with a /dev/disk/by-label check before rollback; fixes a false "Verification failed" caused by
    fatlabel's boot-sector warning (D-1.2.1-01)

1.2.0 - 2026-11-03
  - setup_ventoy_usb.sh now reads its version from the release VERSION file at the repo root
    (SCRIPT_VERSION=x.y.z) instead of a hardcoded value
  - Script exits with an error if VERSION is missing or malformed
  - VERSION file parsed with sed (never sourced)
  - Added VERSION to the file manifest
  - dr_usb_backup.sh -remote: 1:1 SSH/rsync mirror of /boot to a remote server (settings in remote.ini)
  - dr_usb_backup.sh: fixed masked rsync/mount/umount failures; non-zero exit on failure
  - Single release archive Boot-Backup-<version>.tar.gz built by build_release.sh; one root VERSION file
  - Shared code moved into lib/ (logging, drives, clone, config); scripts source it from the install folder
  - dr_usb.ini (optional) replaces the in-script settings block; remote.ini now defaults to beside the scripts
  - dr_usb_create.sh writes usb-create-*.log and removes earlier successful create logs
  - Automated tests in Unit Test/ (run_tests.sh)
  - dr_usb_scrub.sh: maintenance scrub of the live /boot and (-backup) the remote mirror or local UNRAID_DR USB; loud, detailed failure report
  - Hard-stop SHA-256 check of /boot and /boot/previous (against Unraid's .sha256 files) before every backup
  - DR_MANIFEST.sums written onto the UNRAID_DR USB; the restore verifies it plus Unraid's hashes and needs OVERRIDE on failures
  - -remote now requires rrsync on the destination (write-only, one folder, no shell); REMOTE_DIR removed; the script refuses an unrestricted key
  - move_dr_to_unraid.sh rewritten: no longer calls make_bootable_linux; checks first, asks for RESTORE, does the
    relabel / EFI- -> EFI / syslinux install / MBR itself, verifies, and rolls back on failure
  - dr_usb_create.sh: fixed masked failures, unmounts target before wipe, -debug/-lsblk never format, non-zero exit on failure
  - dr_usb_create.sh: new drive menu lists all USB disks (blank and used), marks drives with existing data (*), and
    shows the boot drive, Ventoy USB, mounted and too-small drives as "Not available"
  - dr_usb_create.sh: must run on the Unraid server (startup check); -remote is rejected with an explanation
  - run_logged now logs failure output as ERROR (both scripts); EFI-rename failure now unmounts (both scripts)
  - In-place upgrades from setup_ventoy.ini: Ventoy via Ventoy2Disk.sh -u (data kept), new
    SystemRescue ISO replaces old; full wipe (-I) only as default-no fallback; no Ventoy downgrade
  - setup_ventoy_usb.sh: -upgrade flag kept but prints a deprecation notice (upgrades are automatic)
  - CURRENT_VERSION is now always updated; fixed echo typo that aborted the script
  - Fixed ventoy.json generation (string values, one key per object, VTOY_DEFAULT_IMAGE, backup on overwrite)
  - Updated software versions in setup_ventoy.ini: Ventoy 1.1.18, SystemRescue 13.02
  - NOTE: USBs with CURRENT_VERSION < 1.2.0 will trigger the upgrade path
